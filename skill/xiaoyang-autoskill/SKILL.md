# XiaoYang AutoSkill（xiaoyang-autoskill）

你装上这个 Skill，就按下面的方法把一份逐字稿做成成片。这套方法的核心是：**画面先行、按内容拆组、每组从组件库选件来演，而不是套模板卡片**。组件来自 Yang 动效库（802 件 Remotion 组件），全部在图鉴站上可查、可预览。

## 0. 前置条件

- 一个 Remotion 项目，Remotion 版本对齐 **4.0.537**（所有 `@remotion/*` 包同版本，制作中途不要升级）。
- Node.js 与 ffmpeg 可用。
- 一份定稿逐字稿（纯口播正文）。稿子没定稿之前不要开始拆分镜。

## 1. 组件库怎么访问

- **图鉴站**：https://motion-catalog.pages.dev/ —— 每件一卡：预览、 一句话说明、props、可复制提示词。
- **组件清单（机器可读）**：https://motion-catalog.pages.dev/catalog.json —— 数组，每条字段：
  - `id` 组件唯一名；`name` 显示名；`oneliner` 一句话说清它演什么；
  - `props` / `props_key` 可调参数；`preview` 循环预览地址；`thumbnail` 静帧图；
  - `use` 制作用途（explain 讲解 / recording-focus 录屏聚焦 / images 作品展示 / video-entry 录屏入场 / handoff 段间交接 / data 数据图表）；
  - `intent` 口播在讲什么（statement 结论 / list 列表 / process 流程 / compare 对比 / input 对话 / focus 证据聚焦 / demo 演示 / showcase 展示 / data-num 数据 / transition 转场）；
  - `scene_type` 机制家族（card / text / chart / focus / media / table / timeline / steps / compare / transition / effect / icon / chat / terminal / opener / closer / other）；
  - `tags` 中文标签；`file` 源码在原库中的相对路径。
- **免费单件源码**：`https://motion-catalog.pages.dev/src/<id>.tsx`，把 `<id>` 换成组件 id 即可下载，免注册免付费。共 628 件免费。
- **核心件（付费）**：另有 174 件核心组件不在公开单件下载内，属于 Pro 会员的全库整包内容，本 Skill 不提供它们的下载地址。判断方法：按上面的规则拼出地址后取不到（404），它就是核心件。遇到核心件时：先在免费件里换一个能完成同样对象动作的候选；实在换不到，如实告诉用户「这个组件在 Pro 整包里」，不要试图绕过。
- **许可证**：库内组件为 MIT（yang / remocn / weilanx 来源）与 Apache-2.0（shotcraft 来源）。使用条件：**源码文件头里的版权与出处声明必须原样保留，不许删改**；改动过的 Apache-2.0 文件要注明改动。Remotion 框架本身有自己的许可（个人与小团队免费），渲染交付时自行确认。

## 2. 工作流总览（顺序不要跳）

1. **读逐字稿**：通读全稿，先想清观众起点、核心问题、例子、结论。
2. **按段内容拆画面单元（镜头组）**：见 §3。
3. **每组写清**：这一组要回答的一个问题（oneQuestion）＋画面里看得见的对象和动作。
4. **查图鉴选件**：每组至少比 3 个候选，写选拒理由，见 §4。
5. **收齐素材**：真实素材按 §5 的梯队找齐；缺口先列明，不要等构建时才发现。
6. **建分镜表 / Manifest**：把组、原文区间、选件、素材、交接记成一份单一事实源（模板见 references/storyboard-tables.md）。
7. **构建 Remotion 工程**：按分镜实现每组场景。
8. **配音**：见 §7。配音到位后，以最终音频为准重算帧表。
9. **字幕**：由最终音频生成，见 §8。
10. **分段渲染 → 拼接**：见 §9。
11. **QA**：见 §10，全过才交付。
12. **交付**：成片＋发布物料一次给全，见 §11。

## 3. 拆镜头组：按动作节点切，不按句切

- 先读完整稿再切。找口播里的**动词与关系变化**（打开、对比、落定、汇合、拦下……），它们比自然段更适合决定切点。
- **不按句切，不按自然段切**：一个镜头组可以容纳多句；一句也可以跨两种状态。
- **每组只有一个主要解释任务**，写成 oneQuestion，用观众能看懂的话（如「让观众看清两个耗时差了三倍」），不要写成「用某某组件」。
- 每组写清五项状态责任（不等于必须做五次动画）：
  - `enter` 观众先看到什么（承接上一组末态，或本组如何建立）；
  - `change` 本组发生的可观察变化（谁出现、怎么变、变完留下什么）；
  - `read` 观众要读什么、在哪里停稳；
  - `exit` 本组末态是什么；
  - `handoff` 末态对象如何交给下一组。
- **交接规矩**：上一组末帧＝下一组首帧，同一个对象、同一位置、同一尺寸，靠一个连续动作交接；不用淡入淡出、整屏平移、PPT 式划走。
- 不为避免静止强行切镜：稳定阅读是有效状态。但口播一旦换了对象或结论，画面必须切组或组内换焦点。
- 组内再**逐句核对**：每一句口播里的名词、数字、动作，画面里都要看得见、看得清（逐句动作表见 references/storyboard-tables.md）。

## 4. 选件方法：先写对象动作，再查图鉴

每组按四步走，不跳步：

1. **先写 query**：本组画面里「看得见的对象＋动作」（如「两条耗时赛跑、赛果与快 N 倍胶囊落定」），**不要照抄旁白**。先选组件再往里填字，是返工的头号来源。
2. **查 catalog.json 检索候选**：按 `use` / `intent` / `scene_type` / `tags` / `oneliner` 匹配，至少拿出 **3 个候选**，逐个看 `preview` 预览再决定——只看名字不算看过。
3. **记选拒理由**：写清选了谁、拒了谁、为什么拒。理由必须具体（容量不对、动作关系不对、语义会误导、时长撑不住……），不许只写「不合适」。
4. **都不合适时**：先换说法再查（把 query 拆成更小的对象＋动作、换一个分类维度）；仍没有，就如实**报缺口**，不要退成纯大字页或通用模板卡片，更不要拿生成图冒充真实效果。

整期还要做一次**组件分配检查**：

- 同一「讲解结构类」组件（路线图、方法卡、步骤链、判定卡这类承担讲解结构的）全片默认只出现一次；后面再讲到同一结构，换一种表达。
- 不同段落不要套同一个组件只换字、换图机械推进。同一对象连续出现（如同一份报告连续阅读）不算重复。
- **场景级定制是允许的**：可以拆已选组件的动作，为本组重写时序、删掉它自带的开场和收尾、为接缝重新衔接；场景文件第一行注释写明动作来自哪个组件。

## 5. 素材规矩

- **效果展示 ≠ 出处证据**：讲一个东西的功能或效果时，主画面必须是它实际产出的效果（官方演示视频/GIF、真实成果图，动态素材用原动态呈现）；仓库页、官网截图只算出处背书，作小窗或短暂切入，不许整段铺底冒充效果。
- **素材优先级梯队**（上位有就不下探）：① 当事方官方素材 ＞ ② 大媒体纪录片 ＞ ③ 新闻、报告原文截图 ＞ ④ 人物公开照片 ＞ ⑤ 生成图。生成图只作画中画、短暂切入或背景虚化，不冒充真实素材。
- **证据截图**要推近放大到关键行可读；黄色荧光笔必须精确落在旁白正在讲的那几个字上，没有对应字要圈就不许圈。
- **模拟画面要填实**：表单、报告、文档这类示意画面必须填上真实感的数据与内容，空占位条、空白文档看着假；文档类尽量用真实样本。
- 没有素材可放时，把文字放大来讲，不要大面积空场。

## 6. 画面硬规矩

- **主画面必须是 Remotion 动效讲解**：动态图表、计数、步骤图、kinetic 文字、示意动效。图片只作画中画小插图、短暂切入或背景虚化，不当主画面；镜头推拉＋贴图不等于动效讲解。
- **逐个点亮式呈现禁用**：逐件解锁、逐项点亮作主形式，一律不用。但整表常驻的回扣表、选型表**必须**加随旁白移动的强调高亮：讲到哪行亮哪行、其余行略压暗（但文字仍可读）、念完释放回同亮度。这不算点亮——内容一直在，只是强调跟随。
- **组内元素随旁白逐项出现/强调**：旁白讲到哪、画面出哪，不许整组一次落定。
- **上屏禁标**：画面里不许出现任何「示意／非真实／示例」类说明文字（含小字角标）；重建或示意画面本身可以用，但不打标，素材真假只记在素材清单里。
- **布局按 F 型理论排**：顶部横扫 → 第二横扫 → 左侧纵轴。
- **可读字号**（按 1920×1080 画布等效）：录屏/截图里要读的字 ≥24px，正文 ≥30px；证据页里的关键数据行必须放大到抽帧可读，看不清等于没证据。

## 7. 配音

- 用你自己的 TTS 工具与音色录制。开工前先定**逐段情绪表**（每段用什么情绪），与锁定文本一起作为制作依据，不要录完再补。
- **生成时直接出 1.3 倍速**（语速参数设 1.3），不要先录原速再后期变速——后期变速与直接出，节奏和音质都不同。BGM 保持原速。
- 每次生成后，把接口返回的字幕文件（SRT）一并下载留存备用。
- **画面时间轴必须源于最终音频**：配音到位后重算全局帧表；场景切点与句内节拍（高亮、显影、落定）一律由最终音频的词级时间戳导出，不许用录音前的估时帧表排画面。估时只用于规划阶段，且要标明是估时。

## 8. 字幕

- **先按语义切句，再吸附时间戳**：一句话不许在句中被切断成两条字幕。
- 字幕必须由**最终音频的词级时间戳**生成（对成片音频独立转写得到时间戳），不许用 TTS 计划时长推算。
- 位置：没有角色形象让位需求时，字幕放**底部正中（水平居中）**、底部常规高度；底部只留字幕＋常驻标题两层，不要再堆第三行。
- **烧录前逐行验宽**：单行不许溢出画布（1920 宽画布单行 ≤1350px 等效），超宽按语义拆条/断行；全量检查，不许只抽几行就报干净。

## 9. 渲染与拼接

- 长片按段（part）分段渲染再拼接；渲染脚本的跳过判断要用同一口径的帧数（排他计数与实测帧数恒差 1 会导致永远全量重渲，先修再跑）。
- **拼接禁用裸拼接**：不要用 `ffmpeg -f concat -c copy` 拼 AAC 音频——每段接缝处音频会比视频晚约 0.05 秒，段数越多累积越明显，成片人声系统性滞后。正确做法：用带音频重编码的拼接（filter_complex concat 音视频一起重编），或把音频解成 PCM 按采样点拼接后一次性编码；mux 时显式 `-map` 选轨。
- **拼接后必须做同步速检**：成片音频与配音拼接参考音逐段互相关，任一段滞后 >0.1 秒即返工；验修标准逐段 ≤0.05 秒。
- **BGM**：原速、低音量混入（参考量级：全音量母带乘 0.08 左右），不要给 BGM 变速。
- **响度与峰值**：最终成片音频**真峰值 ≤ −1 dBTP**。测真峰值的步骤在抽不到数值时必须报错停下，不许空值静默放行。

## 10. QA：交付前逐关过

1. **逐句对位**：以成片最终音频的词级时间戳为准，逐句核「旁白讲什么／画面演什么／字幕起止偏差」，目标偏差 ≤0.1 秒。组级对位结论不算数。
2. **实际切点审计**：对成片做切变检测，实际切入时间与句子实际起点逐项比偏差。
3. **素材构成关**：逐组抽帧确认真实素材成规模入画；纯动效卡片组逐组点名说明，不许只报对位与洁净就交付。
4. **素材-句子锁定**：每句旁白都要有绑定的专属素材或明确的动效承担；一句无专属画面、靠上一句画面拖着的，不合格。
5. **理解关**：静音通看全片，只看画面能用一句话说出每段讲了什么、每个对象能干啥，才算过。
6. **带声通听**：通听验音画同步；逐秒查无旁白空档，句间空档 >1 秒要查清原因（只有 BGM 的空档用响度阈值查不出来，要结合词级时间戳看句界）。
7. **冻结判定**：「冻结 ≥1 秒」只指非设计卡死——整帧无任何变化、进度与字幕也停住；落定停稳、阅读停顿这类设计保持不算。判定前先跑一支同结构已交付成片作对照计数，接近即为结构特征。
8. **画面洁净扫描**：查不清晰图像、外来 logo/水印、二维码（素材带出的也算）；上屏禁标为 0。
9. **回扣表高亮核对**：整表类画面逐句抽帧，核对高亮行与旁白所讲项一致。

## 11. 交付

- 成片文件一次给全：成片本体＋标题＋简介＋标签＋封面（如本期需要），并随附成片参数（时长、分辨率、真峰值）。
- 发布由用户本人执行，你不要代发。
- 本期新做的可复用效果，收尾时按组件规范整理，后续可回存组件库。

## 12. 最小完整示例

示例逐字稿（3 句，讲一个查询工具的实测结论）：

> 先看结论：同样跑一万次查询，右边这套只用了左边的三分之一时间。我们把两边的耗时摆在一起，左边 9.6 秒，右边 3.1 秒，差距一眼就看清了。所以别先问它功能多不多，先看它把你要的那件事做得快不快。

拆成 3 个镜头组：

**G01（第 1 句）**
- oneQuestion：让观众先记住结论——右边快 3 倍。
- 对象＋动作：两条耗时赛跑，赛果与「快 3 倍」胶囊落定。
- 选件：**YangABTimeRace**（免费）——它本身就是 A/B 耗时赛跑＋倍数胶囊，对象动作一一对应。
  - 拒 YangScoreBars：评分条带打分语义，会把耗时误读成评分。
  - 拒 YangBenchmarkTable：整张基准表阅读负担太重，一句结论不需要表格。

**G02（第 2 句）**
- oneQuestion：让观众看清 9.6 与 3.1 两个数，以及谁是谁的参照。
- 对象＋动作：两个大数字分两拍依次压到位落定，参照关系同框。
- 选件：**YangSpecLand**（免费）——单个数「盖章式」一次压到位正是这个动作，两个数分两拍各落一次。
  - 拒 YangStatTriplet：三联并列会把两拍压成同时出现，丢掉先后对比。
  - 拒 YangTrendLine：趋势线讲的是变化过程，本组只有两个静态读数。

**G03（第 3 句）**
- oneQuestion：把判断方法钉成一句能带走的话。
- 对象＋动作：结论句落定；前两组的两个数字缩成底行回扣。
- 选件：**YangPillListFill**（免费）——胶囊清单落定适合收束句，底行回扣沿用 G02 的数字对象。
  - 拒 YangNeonMarquee：霓虹跑马灯是气氛特效，会把结论句演成装饰；而且它是核心件，单件源码取不到——选件时先确认能取到再定。

**交接**：G01 末态的两条赛跑条缩小保留，进 G02 作参照；G02 的两个数字在 G03 缩成底行。全程同一批对象连续变化，不黑场、不重排版式。这就是「照着做就能出片」的最小形态：每组先有问题和对象动作，再有选件和理由，最后有交接。
